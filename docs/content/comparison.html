Bedrock Builder versus other tools

Four tools cover most Bedrock work. Each fits one band. This page states the difference so the choice stays simple.

The four bands

Tool Band Use it for
mct (Microsoft) Learn Learn the raw API the official way, follow Microsoft tutorials, validate with the official rule suites.
Bedrock Builder Build and ship Create once, generate linked files, hot reload, ship one file.
bridge. v2 (bridge-core) Edit visually Edit packs in a desktop editor with tree plus text views, presets, auto completions, live previews, com.mojang sync.
Regolith (Bedrock-OSS) Transform at scale Filter pipelines over large multi-pack projects.

Pick Bedrock Builder when

  • Starting a new add-on that must ship, not just teach the API.
  • Hand-wiring items, attachables, textures, and lang lines costs too much time.
  • Hot reload plus one-command packaging must work out of the box.
  • No pipeline config is wanted until the project outgrows one binary.

Pick something else when

  • Learning the raw @minecraft/server API matters most. Use mct.
  • Visual pack editing with previews matters most. Use bridge. v2.
  • Compile-time transforms over many packs matter most. Use Regolith.

Bedrock Builder emits plain standard packs, so a project can move to Regolith or bridge. later with no rewrite. Generation here creates standard files in one command. Generation in Regolith is a compile-time transform. bridge. reads the same folders through its project config standard.
