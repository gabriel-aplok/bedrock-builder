Changelog

Release history for Bedrock Builder.

Unreleased

  • Refuse bb clean and bb build --clean when bb.out is the project itself, a parent, or any folder that holds the config, the packs, or the entry, so a bad out cannot delete sources.
  • Refuse watch and deploy removals whose target escapes the pack destination through .. or a symlinked ancestor.
  • Add an allowScripts entry for esbuild and enable strict-allow-scripts, so an unreviewed dependency install script fails the install instead of running.
  • Ignore .env files in the repo and in the .gitignore that bb init writes.
  • Strip credentials from git, npm, and extension install output before it reaches the console or a report, and add SECURITY.md with a private reporting route.
  • Run afterBundle extension hooks on bb run and bb run --watch, so the dev bundle is post-processed the same way bb build does it.
  • Restore the esbuild-free editor package entry so dist/editor.js ships on a clean build.
  • Stop reporting min_engine_version as newer than a fixed stable release on bb ship.
  • Tolerate missing settings in json-cleaner and strip $schema only from object roots.
  • Keep the perf check on a temp copy of the fixture, so dist/ stops leaking into the repo.
  • Add a json-cleaner extension test, and run the manifest dependency test in a temp project.

0.3.0

  • Add an emit pipeline hook so extensions can generate sourceless files.
  • Mirror remapped file paths in watch mode instead of source paths.
  • Fix bb diff reporting remapped files as modified after a no-op build.
  • Quote windows tool paths with spaces, fixing bb brarchive and installs under such paths.
  • Derive the builder version range from the package itself instead of stale constants.
  • Rewrite nested description identifiers into the project namespace on bb new --from.
  • Check the VS Code extension in CI with typecheck, build, and vsix packaging.
  • Document the VS Code extension under guides.
  • Import resource pack bodies with bb new <type> --from <file>, not just behavior pack ones.
  • Complete --world values from installed worlds in bb completion.
  • Pick the run world and server folder from the VS Code command palette.

0.2.0

  • Replace picocolors, tsup, archiver, and @clack/prompts with in-repo implementations.
  • Fix cache pruning deleting the bundler output directory during parallel builds.
  • Run git and npm through argument arrays, not shell strings.
  • Run checks on Ubuntu and Windows.
  • Add bb init <name> [namespace] and bb init --builder <path>.
  • Check atlas texture files and png sizes in bb harness --strict.
  • Check entry @minecraft/* imports and server version drift in bb check.
  • Check manifest UUIDs, engine version, and the RP to BP link on bb ship.
  • Accept manifest versions as 1.0.0 or [1, 0, 0] everywhere, and reject malformed strings.
  • Import behavior bodies from existing files with bb new <type> --from <file>.
  • Update declared deps, reinstall, and sync the manifest server version with bb update.
  • Print shell completions with bb completion [bash|zsh|powershell].
  • Adopt existing pack folders with bb import [dir].
  • Deploy into a named world with bb run --world <name>.
  • Compile server-optimized packs with bb brarchive (windows only).
  • Deploy to Preview and Store Beta installs with a preview target.
  • Add a loot_table generator plus spawn-egg, recipe unlock, and trade max-uses/xp options.

0.1.0 - first release

  • Create projects with bb init and generate resources with bb new.
  • Bundle scripts, copy both packs, deploy locally, and watch for changes.
  • Validate projects with bb check and bb harness.
  • Create release builds and .mcaddon files with bb ship.
  • Support project-enabled extensions and JSON output for scripts and CI.
  • Provide a JavaScript and TypeScript API.
